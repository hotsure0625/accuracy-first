# 风险分级与 Test Budget Gate

风险来自**行为后果、接口传播范围、变更可逆性、验证证据**，不来自单纯的行数。

| 级别 | 例子（仅供判断） | 最低默认验证 | 人工介入 |
| --- | --- | --- | --- |
| LOW | 文案、非控制流的内部常量、极小且易证明的局部替换 | diff 检查 + 适用的静态检查 | 通常可免人工功能测试 |
| MEDIUM | 一条业务分支、局部异常处理、非关键 API 行为 | 以上 + 编译/类型检查 + 相关定向测试（能跑时） | 视不确定性而定 |
| HIGH | 公共接口、身份授权、安全扫描修复、重要跨模块调用 | 以上 + 调用方检查、针对性回归/集成验证 | 关键行为须审查 |
| CRITICAL | 资金结算、生产数据迁移、密钥/身份授权绕过、不可逆数据更新 | 以上 + 独立审查与覆盖关键故障模式的验证；遵守正式发布门禁 | 不得免去必要人工审批 |

触发升级：外部输入可信度改变、持久化副作用、系统边界改变、重要依赖升级、无法定位调用方、原始行为无规范、存在安全敏感分支。
低风险仍须核实变更确实局部且无跨界影响；一行权限判断也可能属于 CRITICAL。

## 每次写下 Test Budget Gate

- **目标**：修复哪一项行为？
- **必须验证**：最少哪几项检查能支撑结论？
- **可不运行/暂缓**：哪些检查冗余？跳过理由是什么？
- **预算**：预计运行的检查数/耗时上限；预算不足时明确阻断而非假装通过。
- **PASS 条件**：哪些结果允许交付评审？
- **硬停止条件**：何种失败或未知需要升级验证或阻断发布？

## 证明层级（禁止混淆）

- **R0 阅读/推理**：说明可能正确，不能代替验证。
- **R1 Diff 与静态检查**：发现语法、格式或静态规则问题，不能证明运行行为正确。
- **R2 编译/类型检查**：证明特定编译约束通过，不代表业务正确。
- **R3 针对性自动测试**：对已覆盖场景有可执行证据。
- **R4 关键路径集成与回归**：覆盖接口协作和系统边界，仍有覆盖盲区。
- **R5 生产门禁/人工审批**：由项目规定决定，不由 AI 单方跳过。
